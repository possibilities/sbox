# Compatibility and behavior

Sbox implements the familiar Vercel Sandbox development model on Hypeman: create an isolated machine, execute commands, move files, expose a service, and preserve or fork a workspace. Its TypeScript package is `@sbox/sandbox`. Its control plane, authentication, identifiers, pagination records, and HTTP protocol are its own. Changing only a package import is sufficient for many command and file workflows, but it is not a replacement server for an unmodified `@vercel/sandbox` client.

The API comparison below uses the [Vercel Sandbox SDK source](https://github.com/vercel/sandbox/tree/main/packages/vercel-sandbox/src) and [SDK reference](https://vercel.com/docs/sandbox/sdk-reference), inspected against upstream package version 3.6.1. The executable source and tests in this repository are the authority for Sbox behavior.

## SDK surface

| Surface                          | Sbox behavior                                                                                                                                                                                                                                                                                                                                              |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Sandbox.create()`               | Named or generated-name sandbox, OCI image, resources, environment, timeout, tags, ports, persistence, sources, and drive mounts. Hypeman capability checks reject unavailable operations.                                                                                                                                                                 |
| `Sandbox.get()`                  | Lookup by `name`, `sandboxId`, or `id`. `resume: true` waits for a running session. Ordinary retrieval does not boot a stopped machine.                                                                                                                                                                                                                    |
| `Sandbox.getOrCreate()`          | Atomic named creation on one control-plane process. `onCreate` runs for creation; `onResume` runs for a resumed session. Hooks belong to the current client call.                                                                                                                                                                                          |
| `Sandbox.list()`                 | Filter by exact name, name prefix, or tags; sort by name or timestamps. The first page has `items`, `sandboxes`, `nextCursor`, and `pagination`; `toArray()`, `pages()`, and async iteration traverse subsequent pages.                                                                                                                                    |
| `resume()`, automatic resume     | Persistent stopped sandboxes resume before command and file operations. Concurrent operations on one SDK handle share a resume and wait for its hook. Hooks can execute setup commands without deadlocking.                                                                                                                                                |
| `stop()`, `delete()`             | Stop ends processes. Persistent disks remain available for resumption; ephemeral instances are deleted. Deleting an SDK handle makes further operations on it fail. `delete({deleteOrphanSnapshots:true})` also removes unreferenced owned snapshots.                                                                                                      |
| Persistence                      | Persistent stop automatically captures the root filesystem. With the host companion, the original VM is deleted to detach drives and resume restores into a new VM. Without it, the original writable disk is retained. Processes restart after resumption.                                                                                                |
| `snapshot()`, `fork()`           | Explicit stopped-filesystem snapshots and independent forks. The host companion permits CPU, memory, and mount overrides without including external drive contents. Forks do not inherit drive mounts. Base image and root disk capacity remain fixed. Creating a snapshot or forking stops the source.                                                    |
| `extendTimeout()`                | Extends both the control-plane deadline and the guest watchdog deadline. A session is capped at 24 hours.                                                                                                                                                                                                                                                  |
| `update()`                       | Ports, positive timeout increments, credential rotation, and network policy changes affect the current session. Environment, CPU, memory, and mounts are staged for the next session; resource/mount changes require the companion. A stopped sandbox can select `currentSnapshotId` to roll back. `keepLastSnapshots:null` removes count-based retention. |
| `currentSession()`               | Provides a fixed execution identity for commands, files, stop, update, timeout, snapshot, and terminal operations. An ended session cannot silently execute in a replacement session. Historical sessions can be listed with `listSessions()`.                                                                                                             |
| `getCommand()`, `listCommands()` | Reconnect to tracked command metadata and output, including detached commands. A command from another sandbox is rejected by `getCommand()`.                                                                                                                                                                                                               |
| `domain(port)`                   | Returns the configured authenticated preview URL. The server must listen on an interface reachable inside the guest. Preview HTTP and WebSocket connections use the control plane.                                                                                                                                                                         |
| `openInteractive()`              | Returns a short-lived, single-use WebSocket ticket for a PTY. The CLI handles terminal input/output, dimensions, resize, and process exit.                                                                                                                                                                                                                 |
| `createUser()`, `asUser()`       | Guest Linux user contexts, home-relative file paths, command execution as the selected user, and restrictive home permissions. Requires the development image's user-management tools.                                                                                                                                                                     |
| Groups                           | `createGroup()` creates `/shared/<group>` with mode `2770`; membership helpers operate on guest users. Linux permissions enforce sharing.                                                                                                                                                                                                                  |
| `await using`                    | Async disposal stops a sandbox. It does not delete a persistent disk.                                                                                                                                                                                                                                                                                      |

The built-in `runtime:"bun"` selects the standard Bun image. Other legacy `runtime` aliases do not provision a Vercel runtime image. Choose an OCI image containing the required runtime and Bun. Vercel region selection, failover regions, billing metrics, Secure Compute network IDs, Vercel OIDC authentication, and Workflow DevKit serialization are not implemented.

## Commands and streams

`runCommand("program", ["argument"])` executes an argument vector. Shell syntax is literal unless the executable is a shell. A nonzero process exit code resolves to `CommandFinished`; transport failures, session termination, and command timeouts reject.

Object-form options include `cwd`, `env`, `sudo`, `user`, `detached`, `stdin`, `stdout`, `stderr`, `timeoutMs`, and `signal`. Per-command environment entries override sandbox environment entries. Commands default to the guest's `sandbox` user; `sudo: true` selects root. `timeoutMs` also applies to detached commands.

| Command API                        | Behavior                                                                                                                                                   |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `wait()`                           | Waits for the tracked process and returns `CommandFinished`.                                                                                               |
| `logs()`                           | Async iterable of decoded UTF-8 stdout/stderr chunks. Separate streaming decoders preserve characters split across chunks and reconnections.               |
| `rawLogs()`                        | Async iterable with `Buffer` data for byte-preserving protocols and binary tools.                                                                          |
| `stdout()`, `stderr()`, `output()` | Collect complete decoded output. `output()` defaults to both streams in observed order. Concurrent calls share the fetch.                                  |
| Writable output sinks              | Receive original bytes, honor writable completion, and remain open after the command. A failed sink rejects the operation.                                 |
| `stdin: true`                      | Requires detached execution. Use `writeStdin()` and `closeStdin()`. Writes are ordered, chunked, and never automatically retried after uncertain delivery. |
| Readable input                     | Streams bytes to the process, sends EOF on completion, and stops reading if the process exits. The caller's stream is not destroyed.                       |
| `kill()`                           | Sends a supported signal. Aborting an attached command also signals its process. Cancelling log iteration does not kill a detached command.                |

Log reconnection resumes from a monotonically increasing cursor. It does not rerun the command. The server retains a rolling replay window and exposes `command.truncated` when older records are evicted. Active subscribers continue receiving bytes beyond that retention limit. Cursors older than the retained window raise `LOGS_EXPIRED`; slow consumers that exceed their separate bounded queue receive `LOG_CONSUMER_TOO_SLOW`. `poll({after,limit})` exposes bounded pages and the next cursor. Default retention is 16 MiB per command; increasing it is a control-plane configuration choice. Text collection uses replacement characters for invalid UTF-8; use `rawLogs()` or Writable sinks when exact bytes matter.

The control plane tracks active Hypeman exec transports. After a control-plane restart it marks interrupted executions as failed instead of guessing that they completed or running them again. Completed command records and stored output survive a control-plane restart.

## Files

`writeFiles()`, `readFile()`, `readFileToBuffer()`, `downloadFile()`, and `mkDir()` are available on sandboxes, sessions, and user contexts. File contents accept strings or `Uint8Array`, including Buffer. Relative paths start at `/vercel/sandbox`, or at the user's home for a user context. A missing file returns `null` from the direct read helpers.

The `fs` facade provides `readFile`, `writeFile`, `appendFile`, `mkdir`, `readdir`, `stat`, `lstat`, `unlink`, `rm`, `rmdir`, `rename`, `copyFile`, `access`, `exists`, `chmod`, `chown`, `symlink`, `readlink`, `realpath`, `truncate`, and `mkdtemp`. It follows Node-style encoding, flags, and error codes for the supported options. It is not the entire `node:fs/promises` module: file handles, watchers, recursive copy, and every overload are not provided.

Filesystem operations run a fixed Bun helper inside the guest, under the selected user. Data is passed through JSON on stdin, keeping filenames and file contents out of executable source and avoiding argument-size limits. Directory listing preserves hidden files and filenames containing newlines. Appending uses the guest operating system's append mode rather than a read-modify-write sequence. Symlinks are interpreted by the guest filesystem.

Direct reads and downloads stream binary data from the guest without buffering the full file. `writeFiles()` uploads binary request bodies to a temporary sibling, fsyncs, and atomically replaces the destination. A failed upload preserves the previous file. JSON metadata operations retain bounded request/output limits; binary file transfers use separate streaming endpoints.

## Snapshots and drives

`Snapshot.get()`, `list()`, `tree()`, and `delete()` operate on retained snapshot metadata. `tree({ snapshotId, sortOrder: "desc" })` follows parent links toward ancestors. `sortOrder: "asc"` visits all retained descendants in breadth-first order, ordered by creation time within each sibling group. The anchor is separate from the paginated `snapshots`/`items` array; each node reports its snapshot, siblings, and sibling count. Deleted or expired ancestors end that traversal branch. Tree pagination is an Sbox behavior and is not a claim of identical upstream traversal order.

`Drive.getOrCreate()`, `get()`, `list()`, `delete()`, and `fork()` manage independent durable volumes. `drive.snapshot()` returns a mount descriptor; the immutable generation is captured when the sandbox mounts it. A regular readonly mount observes the source volume and does not capture it. Snapshot mounts pin hidden readonly generations, preserving them while sandboxes or snapshots reference them. Writable attachment is exclusive; readonly generations can be shared. An active writer requires the host companion’s atomic filesystem clone; an unattached stable source can be copied without it.

The additional Hypeman `overlay:true` mount option preserves its private writes across native stop/start. Explicit snapshots and VM configuration replacement reject this extension because root-only transplant would discard that separate overlay. Ordinary Vercel-style writable drives and immutable snapshot mounts support the companion snapshot path.

`keepLastSnapshots` supports a count, a retention expiration, and `deleteEvicted:false`. Snapshot expiration can also be selected explicitly. The filesystem backing a stopped persistent sandbox is protected from deletion until that sandbox is deleted or selects another snapshot.

## Networking and compatibility boundaries

The control plane mediates network traffic over an authenticated guest execution channel while Hypeman omits the guest’s external NIC. Policies support domain allowlists, IPv4/IPv6 subnet allow/deny rules, exact/prefix/RE2 request matchers, request-header transforms, `forwardURL`, synthetic responses, and live changes. Real credential values and policy transform secrets stay in private control-plane records; the guest receives mock aliases and the public trust certificate. Updating policy closes existing mediated connections so a prior allowance cannot persist. See [networking](networking.md) for client requirements and address restrictions.

Sbox’s `defineSandboxProxy` verifies its own signed forwarding identity using explicitly configured trusted issuer/public-key options. `getSandboxProxyIdentity()` obtains public setup metadata from an authenticated control plane. The signature binds the original request and destination and has a short expiry and replay checks. This differs from Vercel’s automatic OIDC verification; no Vercel credentials are minted. Service tokens, preview authorization, and PTY tickets are Sbox credentials. Authentication tokens are sent only to the configured API, and authenticated SDK requests reject redirects.

## Coding tools

The supported integration layer is ordinary guest processes, stdio, PTYs, files, and forwarded ports. Codex CLI, Claude Code, OpenCode, Gemini CLI, Aider, MCP stdio servers, and ACP tools can use those interfaces when their binaries, runtime dependencies, and credentials are installed in the chosen image. Presets do not imply that an authenticated model session has been tested on every host.

Use a noninteractive command for automation, a PTY for a terminal UI, and a forwarded port for a tool's server mode. For example, [OpenCode documents](https://opencode.ai/docs/cli/) JSON events with `run --format json`, a server with `serve`, remote `attach`, and ACP over stdin/stdout. Avoid putting progress logs into stdout when bridging a stdio protocol; diagnostics belong on stderr.

There is no automatic import of host API keys or authentication files into guests. Pass selected environment variables or provision guest configuration deliberately. Persistent workspaces can preserve tool session files, while running tool processes still need restarting after a sandbox resumes.

## Verification

The test suite covers API behavior with a fake backend, SDK transport recovery and cancellation, actual execution of the trusted guest filesystem helper, CLI stdio/PTY behavior, and the Hypeman HTTP/WebSocket adapter. The opt-in live suite additionally passed on real Hypeman v0.3.0 / Apple Virtualization VMs, including execution, binary files, users/groups, PTYs, snapshots, drives, HTTP/WebSocket previews, and outbound HTTPS. Codex and Claude Code installation and version checks, plus Codex app-server initialization, were exercised separately; authenticated model inference was not run. See [Hypeman notes](hypeman.md) and [harness verification](harnesses.md).
